One dashboard for your whole homelab.

Nodvard Deck shows you what is going on on your servers, from the Proxmox VM down to a single container. You can also see whether your backups ran. You install it yourself, and for personal use you pay nothing.

Install with three commands View on GitHub

Just want to have a look? Sample data is included. You can throw it out later.

Good to know: the web interface of Nodvard Deck and Nodvard Dock is German only for now. An English interface is planned. This website and the guides are in English.

All views with sample data. Deck is still in beta and runs in Docker on a Raspberry Pi 4 or 5 or on any x86-64 machine.

What Nodvard Deck does

Before Deck changes anything on your servers, it asks you. What it may do without asking is up to you.

Docker with stacks New

Here you see the containers from all your servers together. You edit stacks right in Deck, as text or in a form, or you pull them from a Git repository. If you don’t like an update, you go back to the old version. Your stacks from Portainer come along too, and the volumes stay where they are.

More about Docker

Servers and Proxmox

Every server has its own page in Deck. It shows how busy the server is, which services are running and which updates are pending. You start and stop VMs and LXC on Proxmox right here, and the console opens in your browser. Without Proxmox it works just as well.

More about servers

Nodvard Shield

Shield keeps an eye on your Linux servers. It looks for malware with ClamAV, checks the settings with Lynis and flags SSH logins that don’t look like you. You also see which addresses Fail2ban has banned. By default, findings go straight to quarantine, where you can take them out again at any time. If you don’t want that, turn it off.

More about Shield

Backups

Deck checks whether your Proxmox backups actually ran and tells you when one is missing or went wrong.

Apps

Tiles for your services, so you don’t have to remember addresses anymore. Deck finds containers with a web interface by itself.

Integrations

Uptime Kuma, Home Assistant, Plex, Jellyfin, Synology and a few more get a tile in Deck. Many of them are still in beta.

Vault

Deck stores passwords, API tokens and SSH keys encrypted. If you like, every server gets its own key.

Notifications

Anything that’s off somewhere ends up here. It can go to your phone too, via ntfy, Telegram, Discord or others.

Approvals and accounts

Several users with their own roles, and sign-in with two-factor. The log shows who did what and when.

Green light: done. Yellow light: still in beta.

Only want to manage your containers? Then Nodvard Dock is enough. It’s the Docker part of Deck as its own small image. If you’re about to leave Portainer CE, this is for you. Dock is out since version 0.11.0.

Installed with three commands

All you need is a machine with Docker and Docker Compose. You don’t build anything, the ready-made image comes from GitHub.

In a terminal, with Docker Compose
mkdir ~/nodvard-deck && cd ~/nodvard-deck
curl -fsSL -o compose.yml https://raw.githubusercontent.com/nodvard/deck/main/deploy/compose.standalone.yml
docker compose up -d
What is in compose.yml?

One container, one port, one volume for the data. No Docker socket, no special privileges. The complete file is on GitHub.

name: nodvard-deck
services:
  nodvard-deck:
    image: ghcr.io/nodvard/deck:latest
    restart: unless-stopped
    ports:
      - "${NODVARD_DECK_PORT:-8080}:8080"
    volumes:
      - nodvard_deck_data:/app/data
      # Optional: a folder for backups, for example on a NAS
      # - ./sicherungen:/backups
    healthcheck: …
volumes:
  nodvard_deck_data:
    name: nodvard-deck-data

Then open http://<your-server>:8080 in your browser. You find the setup code with docker compose logs nodvard-deck. At the end, the assistant asks whether you want to look around with sample data first.
