Back up to a NAS or NFS share

Nodvard Deck backs up its own data, encrypted and on a schedule. By default, the backups go to a folder inside the data folder. That protects against mistakes, but not against a broken SD card. A folder on another drive or a NAS is better. Here is how to set it up.

Before you start

Under Settings, System, Backup, first set a backup password (at least 12 characters). Deck then shows the recovery key once. Keep it safe: without the password and the key nobody can open the backups, not even you. That is also where you turn on automatic backups and choose how many backups to keep. The interface is in German for now.

Deck accepts only two targets: /app/data/backups inside the data folder, or the mounted folder /backups and its subfolders, such as /backups/deck. This always means the path inside the container, not the one on the host or the NAS.

  1. Mount the NAS folder on the machine that runs Deck, for example under /srv/backup/deck. For NFS, as a line in /etc/fstab:
    /etc/fstab
    nas:/volume1/backup/deck  /srv/backup/deck  nfs  defaults,_netdev,x-systemd.before=docker.service  0  0

    The NFS share must be mounted before Docker starts. Otherwise Docker mounts the empty folder on the local disk, and the backups end up there instead of on the NAS. _netdev tells the system that it is a network drive, x-systemd.before=docker.service makes Docker wait for it.

  2. Give the folder to the container. Under volumes:, compose.yml already contains a prepared line. Remove the # in front of it and put in your path:
    compose.yml, under volumes:
          - /srv/backup/deck:/backups

    Then run docker compose up -d in the same folder. In Portainer, edit the stack and click “Update the stack”.

  3. Write access for user 1000. Inside the container, Deck runs as user and group 1000. The folder on the NAS must be writable for 1000. Either run chown 1000:1000 for the folder on the NAS, or map all access to 1000 in the NFS export: all_squash,anonuid=1000,anongid=1000.

    With NFS, a chown on the host usually does nothing, because the NAS does not let root through (root_squash).

  4. Test it before you save in the interface. docker ps shows the container name:
    In a terminal
    docker exec -u 1000 <container> sh -c 'touch /backups/.test && rm /backups/.test && echo ok'
  5. Choose it in the interface. If you get ok, enter /backups or a subfolder as the folder under Settings, System, Backup.

If you get a message when saving

The interface shows these messages in German. They mean:

The folder /backups does not exist (is it mounted?)

The line - …:/backups is missing or still commented out, or the container was not recreated afterwards. Run docker compose up -d, in Portainer “Update the stack”.

Backups may only be written to /app/data/backups or the mounted folder /backups

Enter the path inside the container, so /backups or /backups/…, not the path on the host such as /srv/backup/….

Nodvard Deck may not write to /backups

Write access for 1000 is missing (step 3), or the NFS share was not mounted yet when Docker started (step 1).
