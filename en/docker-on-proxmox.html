Managing Docker on Proxmox

Proxmox VE does not ship with Docker. You install it yourself, and the question is where: in a VM or in an LXC container. Here is what the Proxmox documentation says, how to set it up, and how to keep an eye on containers, stacks and backups afterwards.

Note: This website and the guides are in English. The app interface is German only for now.

VM or LXC?

The Proxmox documentation calls nesting containers inside a QEMU VM a recommended practice when you need strong isolation. Application containers in the style of Docker inside LXC are described there as a technology preview. An LXC is lighter but shares the kernel of the Proxmox host. A VM has its own kernel and separates Docker more cleanly from the host.

To get started, create a small Debian or Ubuntu VM and run Docker in it. If you choose LXC, read the notes in the Proxmox documentation on containers first.

Setting up Docker in the VM

  1. Create the VM and install a Linux. Give it enough space for the images and volumes of your containers.
  2. Install Docker and the Compose plugin following the Docker installation guide.
  3. Give every stack its own folder with a compose.yml. That way each stack is easy to find, back up and move.
  4. Add the VM to a Proxmox backup job. A backup of the whole VM then also contains its Compose files and volumes.

How to manage containers

On the command line you use docker compose. If you want a web interface, there are several tools: Portainer and Dockge usually connect additional servers through an agent of their own, while Nodvard Dock and Nodvard Deck reach your servers over SSH without an agent. A comparison is on the Nodvard Dock page.

With Nodvard Deck: Proxmox and Docker in one place

  • The Proxmox page shows nodes, VMs and LXC with their load. You start and stop guests, open the console in the browser, take snapshots and change the hardware.
  • You add the Docker VM as a server over SSH, even with just a username and password. After that you see its containers and stacks, edit Compose files and update images, with a way back if the new image does not start.
  • The Proxmox-Backups module shows guests that are in no backup job. That way you notice if the Docker VM has no backup. How this works is described in Monitor Proxmox backups.
  • Whatever changes something, you either start it yourself or approve it under “Aktionen” (actions). Exceptions are an automation you turn on yourself and the quarantine of Shield, which is on by default and can be turned off.

Deck does not install Docker or your applications for you, and it is in beta. The interface is German only for now. More is on Proxmox and Docker in one dashboard and in the feature overview.

Try it with sample data

Deck installs with three commands, and the sample data shows you everything before your own servers come in. Source code viewable, free for personal use.

In a terminal, with Docker Compose
mkdir ~/nodvard-deck && cd ~/nodvard-deck
curl -fsSL -o compose.yml https://raw.githubusercontent.com/nodvard/deck/main/deploy/compose.standalone.yml
docker compose up -d

Then open http://<your-server>:8080 in your browser. Run docker compose logs nodvard-deck to get your setup code (look for the line starting with “Einrichtungscode”).
