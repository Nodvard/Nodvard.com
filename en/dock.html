Beta Nodvard Dock

The Portainer alternative for your homelab

Nodvard Dock manages containers and Compose stacks on your servers. You move stacks over from Portainer with one click, and the volumes with your data stay. Self-hosted and free for personal use.

InstallOn GitHub

Good to know: the web interface of Nodvard Deck and Nodvard Dock is German only for now. An English interface is planned. This website and the guides are in English.

Why now

In September 2026, Portainer announced that Portainer 3.0 ships without a Community Edition. CE stays on version 2.x and keeps getting security updates and bug fixes there, with only some 3.0 features backported (Portainer blog). If that has you looking for an alternative, Nodvard Dock takes your stacks along.

Move over with one click

In the Stacks tab, every stack created by Portainer has a button to move it over. Dock takes the Compose file and variables from Portainer’s storage, puts them in a folder of their own and deploys the stack there again under the same name. The volumes with your data stay.

If something does not fit, for example because the stored file names other images than the running containers, Dock does not move the stack and tells you why.

What Dock does

  • Containers of all servers on one page: status, start, stop, restart, delete stopped containers, console and details.
  • Logs with a time range, search and download.
  • Stacks: edit them as text or in a form. Before saving, Docker Compose checks the file on the server, and recent versions stay in the history. You create new stacks in a folder on each server, also from templates for Uptime Kuma, Vaultwarden, Nginx Proxy Manager and Gitea.
  • Updates with a way back (rollback): the old image stays as a backup. If the new container does not start, it goes back on its own, except for databases. Whole stacks get “back to the previous version”.
  • Volume backups: before an update, Dock backs up the volumes if you like and checks that there is enough space. You restore them in the Stacks tab.
  • Private registries such as ghcr.io go into the settings, and the password or token is stored in the vault.
  • Images, volumes and networks: list and clean them up.
  • Approval and log: every change is an action with a risk level. The owner decides what runs without asking.

Several servers, no agent

Dock talks to your Docker servers over SSH, and no agent of its own runs on them. If you don’t want to give the account full Docker rights, use the “operate only” mode: Dock may then only call one fixed helper script via sudo, and that script checks every call itself.

What Dock does not do

Dock is made for Docker and Docker Compose on individual servers. It does not manage Docker Swarm or Kubernetes. Dock is in beta, and feedback helps, Discord is the quickest way: discord.gg/gTTs7qMabt.

Installed with three commands

You need a machine with Docker and Docker Compose, for example a Raspberry Pi 4 or 5 with a 64-bit system or an x86-64 machine.

In a terminal, with Docker Compose
mkdir ~/nodvard-dock && cd ~/nodvard-dock
curl -fsSL -o compose.yml https://raw.githubusercontent.com/nodvard/dock/main/compose.yml
docker compose up -d
What is in compose.yml?

One container, one port, one volume for the data. No Docker socket, no special privileges. The complete file is on GitHub.

name: nodvard-dock
services:
  nodvard-dock:
    image: ghcr.io/nodvard/dock:latest
    restart: unless-stopped
    ports:
      - "${NODVARD_DOCK_PORT:-8080}:8080"
    volumes:
      - nodvard_dock_data:/app/data
    healthcheck: …
volumes:
  nodvard_dock_data:
    name: nodvard-dock-data

Then open http://<your-server>:8080. docker compose logs nodvard-dock shows the setup code. If the port is taken, put a file .env next to compose.yml with NODVARD_DOCK_PORT=8081.

Updating: in the same folder, run docker compose pull && docker compose up -d. Your data is kept. Everything else is in the nodvard/dock repository.

Dock or Deck?

Nodvard Dock is just the container manager, as its own lean image. Nodvard Deck includes the same Docker part plus Proxmox, backups, Shield, apps and notifications. It is the same code, with more or less of it included. More in the FAQ.
