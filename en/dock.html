Beta Nodvard Dock

The Portainer alternative for your homelab

Nodvard Dock manages containers and Compose stacks on your servers. You bring simple stacks over from Portainer with a button, and the volumes with your data stay where they are. You host Dock yourself, and it costs nothing for personal use.

InstallView on GitHub

Source code viewable, free for personal use (PolyForm Noncommercial 1.0.0). No agent, just SSH. Compose files live in a folder on the server.

Note: This website and the guides are in English. The app interface is German only for now.

Move Portainer stacks with a button

In the Stacks tab, every stack created by Portainer has the button “Von Portainer übernehmen” (move over from Portainer). Dock grabs the Compose file and variables from Portainer’s storage, puts them in a folder of their own and starts the stack there again under the same name. The volumes with your data stay.

When something doesn’t fit, for example because the stored file lists other images than the running containers, Dock leaves the stack alone and tells you why.

The move works for stacks that Portainer keeps as a single Compose file. Stacks from Git, in several versions or with several files are not supported yet. As long as Portainer is still running in parallel, leave the stack untouched there. If you click delete or rollout in Portainer, Portainer removes the running containers or overwrites them with its old file.

What Dock does

Containers and stacks day to day

  • Containers of all servers on one page: status, start, stop, restart, delete stopped containers, console, details and sorting by state, name, CPU or RAM.
  • Logs with a time range, search and download.
  • Stacks: Edit them as text or in a form. Before saving, Docker Compose checks the file on the server, and recent versions stay in the history. You create new stacks in a folder on each server, also from templates for Uptime Kuma, Vaultwarden, Nginx Proxy Manager and Gitea.
  • Stacks from Git: Pull a version from a Git repository, see what changes first, and go back with “Zurück zum Stand davor” (back to the previous state). If you like, Dock checks the repository for updates on a schedule and sends you a message. Applying it still takes a click.
  • Your own templates: Save a Compose file as a template for new stacks. Environment variables are never included, and Dock refuses hard-coded passwords or tokens when saving, as far as it can spot them.
  • On your phone: Stacks, images, volumes and networks show up as cards instead of cut-off tables. Since 0.14, stack cards show only the main buttons and a “Mehr” (More) menu.

Updates, Git and backups

  • Updates with a way back (rollback): The old image stays as a backup. If the new container does not start, it goes back on its own, except for databases. Whole stacks also get a “Zurück zur vorigen Version” (back to the previous version) button after an update.
  • Volume backups: Before an update, Dock backs up the volumes if you like and checks that there is enough space. You restore them in the Stacks tab.
  • Private registries such as ghcr.io go into the settings, and the password or token is stored in the vault.
  • Pull an image: Download an image by name and tag, private ones with the login under Registries. If it fails, you see why.

Cleanup and control

  • Networks: Create networks, internal only if you like, and connect or disconnect containers. The confirmation warns you if a container would be left without a network.
  • Clean up images (new in 0.14): The Images tab shows the total size of all images and, after a confirmation and approval, cleans up unused images without a name. Afterwards it says how many are gone and how much space was freed.
  • Stopping a stack (new in 0.14): When you stop a stack, you choose whether the containers stay or are removed. The volumes stay.
  • Volumes and networks: List and clean them up.
  • Approval and log: Before Dock changes anything, it asks. As the owner, you decide which actions may go through without asking, and the log shows everything afterwards.

Several servers, no agent

Dock talks to your Docker servers over SSH. You don’t have to install an agent there. Don’t want to give the account full Docker rights? Use the “Nur bedienen” (operate only) mode. With it, Dock may only call one fixed helper script via sudo, and that script checks every call itself. What the helper script may do.

Portainer 3.0 without a Community Edition

In September 2026, Portainer announced that Portainer 3.0 ships without a Community Edition. CE stays on 2.x and keeps getting patches and updates there, but not the 3.x changes. On 6 November, Portainer added that Portainer 3 is Kubernetes-first, not Kubernetes-only, and that no Docker or Podman features are being removed (Portainer blog). If that has you looking for something new, you can take your stacks along to Nodvard Dock.

What Dock does not do

Dock is meant for Docker and Docker Compose on individual servers. It can’t do Swarm or Kubernetes. The interface is only in German so far. And Dock is still in beta, so let me know if something’s off, quickest on Discord.

Install in three commands

You need a machine with Docker and Docker Compose, for example a Raspberry Pi 4 or 5 with a 64-bit system or an x86-64 machine.

In a terminal, with Docker Compose
mkdir ~/nodvard-dock && cd ~/nodvard-dock
curl -fsSL -o compose.yml https://raw.githubusercontent.com/nodvard/dock/main/compose.yml
docker compose up -d
What is in compose.yml?

One container, one port, one volume for the data. No Docker socket, no special privileges; Dock connects to your servers later over SSH. The complete file is on GitHub.

name: nodvard-dock
services:
  nodvard-dock:
    image: ghcr.io/nodvard/dock:latest
    restart: unless-stopped
    ports:
      - "${NODVARD_DOCK_PORT:-8080}:8080"
    volumes:
      - nodvard_dock_data:/app/data
      # Optional: a folder for backups, for example on a NAS
      # - ./sicherungen:/backups
    # healthcheck: see the file on GitHub
volumes:
  nodvard_dock_data:
    name: nodvard-dock-data

Then open http://<your-server>:8080 in your browser. Run docker compose logs nodvard-dock to get your setup code (look for the line starting with “Einrichtungscode”). If the port is taken, put a file .env next to compose.yml with NODVARD_DOCK_PORT=8081.

Updating: in the same folder, run docker compose pull && docker compose up -d. Your data is kept. Everything else is in the nodvard/dock repository.

Dock or Deck?

Nodvard Dock is just the container manager, as its own small image. Nodvard Deck has the same Docker part and adds Proxmox, backups, Shield, apps and notifications on top. The code is the same. Deck just includes more modules. More in the FAQ.
