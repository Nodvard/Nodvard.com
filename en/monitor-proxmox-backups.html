Monitor Proxmox backups

A backup job that fails quietly is often only noticed when you need the backup. Nodvard Deck shows all your Proxmox backups in one list and tells you when a run fails or a backup gets too old. You host Deck yourself (beta, source code viewable, free for personal use).

Note: This website and the guides are in English. The app interface is German only for now.

What Deck shows

  • All backup jobs of your Proxmox servers with schedule and last run.
  • The existing backups for each guest.
  • Guests that are in no job, and failed runs. Both are at the top.

Deck asks for the jobs and backups through the API of your Proxmox VE server.

When Deck tells you

  • Run failed: You get a message, and another one as soon as it works again. Deck only reports when something changes, not at every check.
  • Backup too old: If the last successful backup of a VM or container is older than a limit, Deck tells you once. You set the limit, the default is 3 days. If a job runs less often, the gap from its schedule applies. This also catches the case where nothing fails because the job was deleted or switched off.
  • Test VMs: For VMs and containers that should never be reported, you add an exception.

Messages arrive in Deck and, if you like, on your phone through ntfy, Telegram, Discord or one of the other channels. During a maintenance window they only go to the history, without a push.

How to set it up

  1. Turn on the Proxmox-Backups module.
  2. Open the Proxmox page and choose “Mit Passwort verbinden” (connect with password). This needs admin rights in Deck.
  3. Enter the address of your Proxmox and compare the certificate fingerprint with the one in Proxmox.
  4. Enter the user and password of a Proxmox administrator, usually root@pam. Under “Was darf Nodvard Deck?” (what may Nodvard Deck do?) choose between “Nur ansehen” (view only) and “Ansehen und steuern” (view and control), and leave “Auch Proxmox-Backups verbinden” (also connect Proxmox backups) on.

Deck only needs the password for this one login. Afterwards it creates a user of its own with an API token for the backups in Proxmox and forgets the password. If you choose “Nur ansehen” (view only), Deck can only read. How this works in detail and which rights the access gets is described in the guide to the Proxmox token.

What you can do from Deck

With “Ansehen und steuern” (view and control) you start a backup right away or retry a run. You create backup jobs and change them. And you restore a backup as a copy, the original stays untouched. Each of these actions goes through an approval and is written to the log.

What Deck does not do

  • Deck does not back up your VMs and containers itself. Proxmox makes the backups, Deck shows whether they run.
  • A backup in the same storage as the original does not protect you if that storage fails. And a backup you never restored is untested. Try restoring as a copy once.

Try it with sample data

Deck installs with three commands, and the sample data shows you everything before your own servers come in. Source code viewable, free for personal use.

In a terminal, with Docker Compose
mkdir ~/nodvard-deck && cd ~/nodvard-deck
curl -fsSL -o compose.yml https://raw.githubusercontent.com/nodvard/deck/main/deploy/compose.standalone.yml
docker compose up -d

Then open http://<your-server>:8080 in your browser. Run docker compose logs nodvard-deck to get your setup code (look for the line starting with “Einrichtungscode”).
