Beta Nodvard Dock

Die Alternative zu Portainer für dein Homelab

Nodvard Dock verwaltet Container und Compose-Stacks auf deinen Servern. Deine Stacks aus Portainer holst du per Knopf rüber, und die Volumes mit deinen Daten bleiben, wo sie sind. Du hostest Dock selbst, privat kostet es nichts.

InstallierenAuf GitHub

Warum gerade jetzt

Portainer hat im September 2026 angekündigt, dass Portainer 3.0 ohne Community Edition erscheint. CE bleibt bei Version 2.x und bekommt dort weiter Sicherheitsupdates und Fehlerbehebungen, Neues aus 3.0 nur noch vereinzelt (Portainer-Blog). Wenn du deshalb nach etwas Neuem suchst, kannst du deine Stacks zu Nodvard Dock mitnehmen.

Umziehen per Knopf

Im Reiter Stacks hat jeder Stack, den Portainer angelegt hat, den Knopf „Von Portainer übernehmen“. Dock holt sich Compose-Datei und Variablen aus dem Speicher von Portainer, legt sie in einen eigenen Ordner und startet den Stack dort unter demselben Namen neu. Die Volumes mit deinen Daten bleiben.

Wenn etwas nicht passt, zum Beispiel weil in der gespeicherten Datei andere Images stehen als in den laufenden Containern, lässt Dock den Stack in Ruhe und sagt dir, warum.

Was Dock kann

  • Container aller Server auf einer Seite: Zustand, Starten, Stoppen, Neustarten, gestoppte Container löschen, Konsole und Details.
  • Logs mit Zeitraum, Suche und Download.
  • Stacks als Text oder im Formular bearbeiten. Vor dem Speichern prüft Docker Compose die Datei auf dem Server, die letzten Stände bleiben im Verlauf. Neue Stacks legst du je Server in einem Ordner an, auch aus Vorlagen für Uptime Kuma, Vaultwarden, Nginx Proxy Manager und Gitea.
  • Update mit Rückweg (Rollback): Das alte Image bleibt als Sicherung. Startet der neue Container nicht, geht es von selbst zurück, außer bei Datenbanken. Auch für ganze Stacks gibt es nach einem Update den Knopf „Zurück zur vorigen Version“.
  • Volume-Sicherungen: Vor einem Update sichert Dock auf Wunsch die Volumes und prüft, ob genug Platz da ist. Im Reiter Stacks spielst du sie wieder zurück.
  • Private Registries wie ghcr.io trägst du in den Einstellungen ein, das Passwort oder Token liegt im Tresor.
  • Images, Volumes und Netze auflisten und aufräumen.
  • Freigabe und Protokoll: Bevor Dock etwas ändert, fragt es nach. Welche Aktionen ohne Rückfrage durchlaufen dürfen, stellst du als Inhaber selbst ein, und im Protokoll steht hinterher alles.

Mehrere Server, kein Agent

Dock redet per SSH mit deinen Docker-Servern. Einen Agent musst du dort nicht installieren. Du willst dem Zugang keine vollen Docker-Rechte geben? Dann nimm den Modus „Nur bedienen“. Damit darf Dock per sudo nur ein festes Hilfsskript aufrufen, und das prüft jeden Aufruf selbst.

Dock, Portainer CE und Dockge im Vergleich

Alle drei verwalten Container mit Compose. Unterschiedlich ist vor allem, wie weitere Server dazukommen und wo die Compose-Dateien liegen.

Was Dock nicht kann

Dock ist für Docker und Docker Compose auf einzelnen Servern gedacht. Swarm und Kubernetes kann es nicht. Die Oberfläche gibt es bisher nur auf Deutsch. Und Dock ist noch Beta, also sag gern Bescheid, wenn was hakt, am schnellsten auf Discord.

In drei Befehlen installiert

Du brauchst einen Rechner mit Docker und Docker Compose, etwa einen Raspberry Pi 4 oder 5 mit 64-Bit-System oder einen x86-64-Rechner.

Im Terminal, mit Docker Compose
mkdir ~/nodvard-dock && cd ~/nodvard-dock
curl -fsSL -o compose.yml https://raw.githubusercontent.com/nodvard/dock/main/compose.yml
docker compose up -d
Was steht in der compose.yml?

Ein Container, ein Port, ein Volume für die Daten. Kein Docker-Socket, keine besonderen Rechte. Die vollständige Datei liegt auf GitHub.

name: nodvard-dock
services:
  nodvard-dock:
    image: ghcr.io/nodvard/dock:latest
    restart: unless-stopped
    ports:
      - "${NODVARD_DOCK_PORT:-8080}:8080"
    volumes:
      - nodvard_dock_data:/app/data
      # Optional: Ordner für Sicherungen, etwa auf einem NAS
      # - ./sicherungen:/backups
    healthcheck: …
volumes:
  nodvard_dock_data:
    name: nodvard-dock-data

Dann http://<dein-server>:8080 öffnen. Den Einrichtungscode zeigt docker compose logs nodvard-dock. Wenn der Port belegt ist, leg neben die compose.yml eine Datei .env mit NODVARD_DOCK_PORT=8081.

Aktualisieren: im selben Ordner docker compose pull && docker compose up -d. Deine Daten bleiben erhalten. Alles Weitere steht im Repository nodvard/dock.

Dock oder Deck?

Nodvard Dock ist nur die Container-Verwaltung, als eigenes, kleines Image. Nodvard Deck hat denselben Docker-Teil und obendrauf Proxmox, Backups, Shield, Apps und Meldungen. Der Code ist derselbe, es ist nur unterschiedlich viel drin. Mehr in den häufigen Fragen.

Portainer ist eine Marke ihres Inhabers. Nodvard steht in keiner Verbindung dazu.
