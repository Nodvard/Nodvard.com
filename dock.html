Beta Nodvard Dock

Die Alternative zu Portainer für dein Homelab

Nodvard Dock verwaltet Container und Compose-Stacks auf deinen Servern. Stacks aus Portainer übernimmst du mit einem Klick, die Volumes mit deinen Daten bleiben. Selbst gehostet und für private Nutzung kostenlos.

In 2 Schritten installierenAuf GitHub

Warum gerade jetzt

Portainer hat im September 2026 angekündigt, dass Portainer 3.0 ohne Community Edition erscheint. CE bleibt bei Version 2.x und bekommt dort weiter Sicherheitsupdates und Fehlerbehebungen, Neues aus 3.0 nur noch vereinzelt (Portainer-Blog). Wenn du deshalb nach einer Alternative suchst, nimmt Nodvard Dock deine Stacks mit.

Umzug mit einem Klick

Im Reiter Stacks steht bei jedem Stack, den Portainer angelegt hat, der Knopf „Von Portainer übernehmen“. Dock holt Compose-Datei und Variablen aus dem Speicher von Portainer, legt sie in einen eigenen Ordner und rollt den Stack dort unter demselben Namen neu aus. Die Volumes mit deinen Daten bleiben.

Passt etwas nicht, etwa weil die gespeicherte Datei andere Images nennt als die laufenden Container, zieht Dock nicht um und nennt den Grund.

Was Dock kann

  • Container aller Server auf einer Seite: Zustand, Starten, Stoppen, Neustarten, gestoppte Container löschen, Konsole und Details.
  • Logs mit Zeitraum, Suche und Download.
  • Stacks als Text oder im Formular bearbeiten. Vor dem Speichern prüft Docker Compose die Datei auf dem Server, die letzten Stände bleiben im Verlauf. Neue Stacks legst du je Server in einem Ordner an, auch aus Vorlagen für Uptime Kuma, Vaultwarden, Nginx Proxy Manager und Gitea.
  • Update mit Rückweg: Das alte Image bleibt als Sicherung. Startet der neue Container nicht, geht es von selbst zurück, außer bei Datenbanken. Ganze Stacks aktualisierst du mit „Zurück zur vorigen Version“.
  • Volume-Sicherungen: Vor einem Update sichert Dock auf Wunsch die Volumes und prüft, ob genug Platz da ist. Im Reiter Stacks spielst du sie wieder zurück.
  • Private Registries wie ghcr.io trägst du in den Einstellungen ein, das Passwort oder Token liegt im Tresor.
  • Images, Volumes und Netze auflisten und aufräumen.
  • Freigabe und Protokoll: Jede Änderung ist eine Aktion mit Risikostufe. Was ohne Rückfrage durchläuft, bestimmt der Inhaber.

Mehrere Server, kein Agent

Dock spricht per SSH mit deinen Docker-Servern, auf den Servern läuft kein eigener Agent. Wer dem Zugang keine vollen Docker-Rechte geben will, nutzt den Modus „Nur bedienen“: Dock darf dort per sudo dann nur ein festes Hilfsskript aufrufen, das jeden Aufruf selbst prüft.

Was Dock nicht kann

Dock ist für Docker und Docker Compose auf einzelnen Servern gemacht. Docker Swarm und Kubernetes verwaltet es nicht. Die Oberfläche ist derzeit auf Deutsch. Dock ist Beta, Rückmeldungen helfen, am schnellsten auf Discord.

In 2 Schritten installiert

Du brauchst einen Rechner mit Docker und Docker Compose, etwa einen Raspberry Pi 4 oder 5 mit 64-Bit-System oder einen x86-64-Rechner.

  1. Die Compose-Datei holen.
    Im Terminal
    mkdir ~/nodvard-dock && cd ~/nodvard-dock
curl -fsSL -o compose.yml https://raw.githubusercontent.com/nodvard/dock/main/compose.yml
  2. Starten.
    Im selben Ordner
    docker compose up -d

    Dann http://<dein-server>:8080 öffnen. Den Einrichtungscode zeigt docker compose logs nodvard-dock. Ist der Port belegt, leg neben die compose.yml eine Datei .env mit NODVARD_DOCK_PORT=8081.

Aktualisieren: im selben Ordner docker compose pull && docker compose up -d. Deine Daten bleiben erhalten. Alles Weitere steht im Repository Nodvard/Dock.

Dock oder Deck?

Nodvard Dock ist nur die Container-Verwaltung, als eigenes, schlankes Image. Nodvard Deck bringt denselben Docker-Teil mit und dazu Proxmox, Backups, Shield, Apps und Meldungen. Es ist derselbe Code, nur unterschiedlich viel drin. Mehr in den häufigen Fragen.

Portainer ist eine Marke ihres Inhabers. Nodvard steht in keiner Verbindung dazu.
