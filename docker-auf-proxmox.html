Docker auf Proxmox verwalten

Proxmox VE bringt Docker nicht mit. Du installierst es selbst, und die Frage ist, wo: in einer VM oder in einem LXC-Container. Hier steht, was die Proxmox-Dokumentation dazu sagt, wie du es einrichtest und wie du Container, Stacks und Sicherungen danach im Blick behältst.

VM oder LXC?

Die Proxmox-Dokumentation nennt es eine bewährte Praxis, Container in einer QEMU-VM zu verschachteln, wenn du viel Trennung brauchst. Anwendungs-Container im Stil von Docker im LXC gelten dort als Technologievorschau. Ein LXC ist leichter, teilt aber den Kernel des Proxmox-Hosts. Eine VM hat einen eigenen Kernel und trennt Docker sauberer vom Host.

Für den Einstieg heißt das: Leg eine kleine Debian- oder Ubuntu-VM an und betreibe Docker darin. Wer LXC wählt, sollte die Hinweise in der Proxmox-Dokumentation zu Containern vorher lesen.

Docker in der VM einrichten

  1. Lege die VM an und installiere ein Linux. Gib ihr genug Platz für die Images und Volumes deiner Container.
  2. Installiere Docker und das Compose-Plugin nach der Anleitung von Docker.
  3. Lege für jeden Stack einen eigenen Ordner mit einer compose.yml an. So ist jeder Stack einzeln zu finden, zu sichern und zu verschieben.
  4. Nimm die VM in einen Backup-Job von Proxmox auf. Die Sicherung der ganzen VM enthält dann auch ihre Compose-Dateien und Volumes.

Wie du Container verwaltest

Auf der Kommandozeile geht es mit docker compose. Willst du es in einer Weboberfläche, gibt es mehrere Werkzeuge: Portainer und Dockge binden weitere Server in der Regel über einen eigenen Agent an, Nodvard Dock und Nodvard Deck gehen ohne Agent per SSH an die Server. Eine Gegenüberstellung steht auf der Seite Nodvard Dock.

Mit Nodvard Deck: Proxmox und Docker an einem Ort

  • Die Proxmox-Seite zeigt Knoten, VMs und LXC mit Auslastung. Du startest und stoppst Gäste, öffnest die Konsole im Browser, legst Snapshots an und änderst die Hardware.
  • Die Docker-VM trägst du als Server per SSH ein, auch nur mit Benutzer und Passwort. Danach siehst du ihre Container und Stacks, bearbeitest Compose-Dateien und aktualisierst Images, mit einem Rückweg, falls das neue Image nicht startet.
  • Das Modul Proxmox-Backups zeigt Gäste, die in keinem Backup-Job stecken. So fällt auf, wenn die Docker-VM keine Sicherung hat. Wie das geht, steht in Proxmox-Backups überwachen.
  • Was etwas verändert, startest du selbst oder gibst es unter „Aktionen“ frei. Ausnahmen sind eine Automatik, die du selbst einschaltest, und die Quarantäne von Shield, die ab Werk an ist und sich abschalten lässt.

Deck installiert weder Docker noch deine Anwendungen für dich, und es ist Beta. Die Oberfläche gibt es bisher nur auf Deutsch. Mehr dazu steht unter Proxmox und Docker in einem Dashboard und in der Funktionsübersicht.

Probier es mit Beispieldaten aus

Installiert ist Deck in drei Befehlen, und die Beispieldaten zeigen dir alles, bevor deine eigenen Server dazukommen. Quelltext einsehbar, kostenlos für den privaten Gebrauch.

Im Terminal, mit Docker Compose
mkdir ~/nodvard-deck && cd ~/nodvard-deck
curl -fsSL -o compose.yml https://raw.githubusercontent.com/nodvard/deck/main/deploy/compose.standalone.yml
docker compose up -d

Danach öffnest du http://<dein-server>:8080 im Browser. Den Einrichtungscode zeigt docker compose logs nodvard-deck.
