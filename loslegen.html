Loslegen

Nodvard Deck läuft in Docker, egal ob auf einem Raspberry Pi 4 oder 5 oder auf einem x86-64-Rechner. Bauen musst du nichts, das fertige Image kommt von GitHub (ghcr.io/nodvard/deck, für arm64 und x86-64).

  1. Docker und Docker Compose bereitstellen. Auf einem Raspberry Pi brauchst du ein 64-Bit-System.
  2. Deck holen und starten.
    Im Terminal
    mkdir ~/nodvard-deck && cd ~/nodvard-deck
curl -fsSL -o compose.yml https://raw.githubusercontent.com/nodvard/deck/main/deploy/compose.standalone.yml
docker compose up -d
    Was steht in der compose.yml?

    Ein Container, ein Port, ein Volume für die Daten. Kein Docker-Socket, keine besonderen Rechte. Die vollständige Datei liegt auf GitHub.

    name: nodvard-deck
services:
  nodvard-deck:
    image: ghcr.io/nodvard/deck:latest
    restart: unless-stopped
    ports:
      - "${NODVARD_DECK_PORT:-8080}:8080"
    volumes:
      - nodvard_deck_data:/app/data
      # Optional: Ordner für Sicherungen, etwa auf einem NAS
      # - ./sicherungen:/backups
    healthcheck: …
volumes:
  nodvard_deck_data:
    name: nodvard-deck-data

    Unter Windows sind das Befehle für WSL oder Git Bash. In PowerShell schreibst du curl.exe statt curl und führst die Befehle einzeln aus.

  3. Im Browser öffnen: http://<dein-server>:8080. Deck fragt nach einem Einrichtungscode. Den zeigt docker compose logs nodvard-deck im selben Ordner, die Zeile beginnt mit „Einrichtungscode“.
  4. Dem Assistenten folgen. Er führt dich durch dein Konto und den ersten Server. Wer erst mal nur schauen will, nimmt Beispieldaten und wirft sie später wieder raus.

Port schon belegt?

Leg neben die compose.yml eine Datei .env mit der Zeile NODVARD_DECK_PORT=8081 und führe docker compose up -d noch einmal aus. Deck ist dann unter Port 8081 erreichbar.

Aktualisieren

Im selben Ordner docker compose pull && docker compose up -d. Deine Daten bleiben erhalten. Vor jedem Update, das die Datenbank umbaut, legt Deck selbst eine Kopie an.

Nach der Installation

Als Erstes solltest du die Sicherung einrichten, am besten auf ein NAS: Sicherungen auf ein NAS oder NFS. Was du zu Lizenz, Daten oder Raspberry Pi wissen willst, steht in den häufigen Fragen.
